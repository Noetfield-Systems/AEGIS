# Premium Product Design System — AEGIS Obsidian v2

## Reference
Founder-provided 1648×928 reference screenshot, 2026-11-13. Inspiration only: independent HTML/CSS rather than using the screenshot as non-interactive background. Design specification is authoritative for later pixel refinements.

## Identity
Luxury enterprise / sober evidence laboratory. Midnight obsidian (#090D1A), panel ink (#151A2B), dark plum (#30213F), champagne (#D6AE74), violet (#A48DDC), positive mint (#68D9B6), critical coral (#F07C96), high-legibility ivory (#F2ECED). Gold reserved for focus, selected nav and important interaction; red only for blocked/failed.
Inter for English/French UI, Georgia for AEGIS identity. Both website locales are LTR. No Persian font, RTL website layout or FA language option. No fake badges, fabricated user avatars, decorative numbers, fake skyline as evidence, or simulated system connectivity.

## Information architecture
Top: authenticated profile / workspace, language switch, export & add evidence. Persistent nav: overview, scored criteria, gaps, evidence, pilot, tasks, external activities, team, commercialization, risk, audit. Main cockpit: score donut + mandatory gates + trend + scenario caveat + next action queue. Responsive sidebar collapses to scrollable navigation on mobile. Forms are edit-preserving and maintain data validation.
Minimum 44px pointer target for core nav. Reduced motion honoured. State focus ring >=2px, keyboard access to forms, contrast review under WCAG 2.2 AA, screen reader labels and semantic status language required.

## Localization requirements

All AEGIS website experiences (private ISC Readiness Studio, interactive Assurance Workbench, public demo and audit exports) use **English en-CA by default and French fr-CA as the sole alternate language**. LTR only. Do not translate, mutate, or misrepresent underlying user-entered evidence, source quotes, policy text or document hashes. English and French copy must both accurately distinguish a synthetic technical finding from official regulatory compliance.

## Guided Assurance Workbench — November 18, 2026

A six-stage instrument panel in the existing Obsidian/Champagne identity:
1. Context: visible synthetic AI system inventory, controls, versioned policy source identity.
2. Policy: literal before/after policy excerpts and official source references with explicit source limitations.
3. Evaluate: real authenticated first-party native evaluation, changed technical findings and lifecycle queue.
4. Review: case receipt, internal operator record, required justification, hash-linked journal history.
5. Report: downloadable, print-ready EN/FR HTML dossier with policy lineage, native measurements, review event, receipt and research constraints.
6. ISC acceptance: transparent partial E1–E6 engineering matrix, traceable tested code artifacts and explicit missing proof.

The UI makes no independent government endorsement, actual TRL 5 or Canadian hosting claim. Design QA: semantic heading structure, keyboard focus, mobile/desktop layout, reduced motion, safe DOM text, empty/error/expired-session paths and locale parity. A real-browser human visual and accessibility audit remains a separate acceptance gate.

## Operational UX
Every displayed score is observed internal evidence only. Scenario scores 43/102/120 explicitly labelled hypothetical. Show owner, date, blocker, next action on tasks. A rejected/deleted exhibit recalc immediately. Do not turn a simulated milestone into Done. No optimistic mark "production-ready" until test record and actual independent review.
